PHASE 0 PROMPTS — Setup & Architecture
Prompt P0.1 — Docker Compose Setup
Create a Docker Compose file for a Node.js microservices project with these services: PostgreSQL 15, Redis 7, MongoDB 6, and a basic API Gateway using Node.js + Express. Include health checks, volume mounts, and a shared network. Environment variables should come from a .env file. Also create the .env.example file with all required variables for: DB credentials, Redis URL, MongoDB URI, JWT secrets (access + refresh), Twilio Account SID + Auth Token, Firebase project credentials, AWS S3 bucket + credentials, and Google Maps API key.

Prompt P0.2 — Prisma Schema
Create a complete Prisma schema (schema.prisma) for a CCTV installation management platform with these models: User (with roles: super_admin, dispatcher, technician, client, site_manager), Technician (extends User, with GPS location, skills array, availability status), Client (organization details, is_high_security boolean), Site (GPS coordinates, geofence radius, FK to client and site_manager), Job (full status machine: pending→assigned→en_route→checked_in→in_progress→completed→cancelled, FK to client/site/technician), JobSurvey (camera details, DVR info, cable length, photo arrays), InventoryItem (SKU, category, stock levels), JobMaterial (junction: job ↔ inventory with quantity), LocationPing (high-volume GPS history), AuditLog (immutable event log with JSONB old/new values). Add all necessary indexes. Use PostgreSQL provider.


PHASE 1 PROMPTS — Backend Services
Prompt P1.1 — Auth Service
Build a complete Auth Service in Node.js + TypeScript + Express with these features: (1) Phone OTP login using Twilio Verify API — send OTP, verify OTP, (2) JWT access tokens (15 min expiry) + refresh tokens (7 days, HttpOnly cookie), (3) RBAC middleware — accepts role array, validates JWT + checks user role, (4) Token refresh endpoint, (5) Logout (invalidate refresh token in Redis blacklist). Use Prisma for DB. Include proper error handling, input validation with Zod, and rate limiting on OTP endpoint (max 3 requests per phone per 10 min). Write the complete working code with all routes, controllers, middleware, and a Swagger/OpenAPI spec.

Prompt P1.2 — Location Service with PostGIS
Build a Location Service in Node.js + TypeScript with: (1) REST endpoint POST /location/ping — receives lat/lng from technician app, stores in PostgreSQL location_pings table using raw Prisma SQL with PostGIS geometry, updates technician current_lat/current_lng in Redis (key: "tech:location:{id}", TTL 5 min), (2) WebSocket (Socket.io) — namespace "/location", room per technician ID, admin can subscribe to all or specific rooms, (3) GET /location/technicians — returns all technicians with status=available|busy and their current location from Redis, (4) GET /location/nearest?lat=X&lng=Y&radius=50000 — uses PostGIS ST_DWithin to find available technicians within radius km, returns ranked by distance + current job count. Write the complete implementation with Socket.io setup and PostGIS raw queries.

Prompt P1.3 — Job Service State Machine
Build a Job Service in Node.js + TypeScript + Prisma with a proper state machine. States: pending → assigned → en_route → checked_in → in_progress → completed (also: cancelled from any state). Implement: (1) POST /jobs — create job, generate job_number (SSE-YYYYMMDD-NNN format), (2) PATCH /jobs/:id/assign — assign technician (manual or auto), validate technician availability, update their status to busy, send FCM push notification via Notification Service (HTTP call), (3) POST /jobs/:id/checkin — validate GPS coordinates within 100m of site geofence using Haversine formula, if site.is_high_security trigger OTP generation, (4) POST /jobs/:id/otp/verify — verify OTP against Auth Service, mark otp_verified=true, transition to in_progress, (5) POST /jobs/:id/complete — accept survey data, photos array, client_signature_url, transition to completed, trigger Report Service. Write complete code with all validations.
